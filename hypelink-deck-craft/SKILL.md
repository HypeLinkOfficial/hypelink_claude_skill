# Skill：做出一份好簡報

順序不能跳：先想清楚對誰說什麼，最後才做視覺。

## 1. 動手前先回答四題

1. **聽眾是誰？** 投資人、學生、客戶要的東西不同，語氣也不同。
2. **聽完要做什麼？** 寫成一個動作，例如「約下一次會議」或「離場時有一個公開的品牌頁」。
3. **現場怎麼用？** 自己講、寄給人讀、還是帶大家操作。寄送版的字要能獨立成立，實作版要看得清楚、打得出來。
4. **手上有哪些真實證據？** 先盤點數字、案例與產品畫面，再決定論點。

答案已在需求或素材裡就直接用，不要反問。

## 2. 依目的選骨架

| 類型 | 順序 | 重點 |
|---|---|---|
| 募資 | 最強證據 → Why Now → 痛點 → 市場 → 競爭 → 模式 → 現況 → 財務 → 團隊 → Ask | 正文 12～16 頁，細節放感謝頁後的附錄 |
| 工作坊 | 帶走什麼 → 概念 → 判斷標準 → 工具操作 → 一步一頁實作 → 卡住怎麼辦 → 下一步 | 先確認學員的方案和帳號能走完全程 |
| 演講 | 一個反差 → 三個論點 → 一句話收尾 | 每頁只放一個想法 |
| 作品提案 | 對方的問題 → 相關作品 → 做法 → 成果 → 合作方式 | 只放和這位客戶有關的作品 |

開場放最強的東西，不要從背景講起。收尾給一個明確的下一步。

## 3. 標題是整份簡報的摘要

- 只讀標題，就要能讀完整個故事。
- 標題寫主張，不寫分類。「功能比較」改成「整合度領先，規模待建立」。
- 精簡和有主張不衝突，一行內寫完。
- 一頁一個重點；放不下就拆頁或移到附錄。

## 4. 數字與說服力的底線

- **絕不捏造**數字、客戶、額度或急迫感，也不要替使用者估算沒有依據的值。
- 沒有的資料不留 TBD 或空格。請使用者補，或改用能查證的論點。
- 推算值要標「概算」，情境預測要標「情境」，示範數字要標「示範」。
- 事實要回到來源查。功能與方案限制以官方文件當下的內容為準。
- 整排都贏的競品表沒人相信，主動列出自己的弱項。
- 想讓人覺得「現在不投會錯過」，靠的是真實的動能、稀缺與時限。簡報只能放大，不能憑空製造。
- 使用客戶名稱或案例前，先確認對方同意。

## 5. 視覺

- 從活動或品牌的既有素材取風格（海報、Logo、產品），不要套通用模板。
- 文字對比優先，背景圖一定要調淡或加遮罩，看過才算數。
- **照片**：用可商用的圖庫，例如 Pexels、Unsplash。先看過再選，避開畫面上有其他品牌或競品介面的圖。
- **情境圖放在案例旁**要標「情境示意」，不可放陌生人冒充團隊。
- **產品畫面**優先用真實截圖；對外展示時遮掉或換掉真實客戶資料。
- **動態**只放在輔助元素。動得太多，聽眾會看動畫而不是聽你講。

## 6. 帶實作的工作坊

- 一步一頁，Prompt 短到看投影就能打字。
- 每個 Prompt 都寫「先給我看，我確認了再更新」，並禁止 AI 編造。
- 明確標出 AI 做不到、要手動的步驟。
- 準備一頁疑難排解，內容來自官方文件的常見問題。
- 寫下免費帳號的替代路線。
- **上台前用自己的帳號完整走一次**，投影片看起來對，不代表流程走得通。

## 7. 用 HypeLink 極速簡報做出來

沒有連 HypeLink MCP 時，前六節仍然適用，改用使用者手邊的簡報工具即可。

1. 用 `decks.list` 看有沒有可沿用的簡報，用 `decks.sources` 取得作品、服務、商品、活動的 uuid。
2. 先把大綱和每頁標題給使用者確認，確認後才建立。
3. 用 `decks.create` 建立，**務必帶 `visibility: "private"`**，因為預設是公開的。要先檢查參數可帶 `dry_run: true`。
4. 內建內容用 `items` 排順序；需要自己寫的頁面用 `decks.pages.upsert` 新增，`position` 決定插入位置。
5. 把演講內容寫進 `speakerNotes`，只有簡報筆看得到。
6. 用 `transition`、`entrance`、`layout`、`mediaMode`、`theme`、`accentColor` 調整整體風格，一份簡報選定一種就好。
7. 使用者確認內容後，才把 `visibility` 改成 `public` 或 `password`。

容易出錯的地方：

- `items`、`pages`、`speakerNotes` 都是**整組取代**。修改前先用 `decks.get` 取回完整內容；只改一頁就用 `decks.pages.upsert`。
- 畫布是 1600×900。內容超過一頁時，播放要捲動，PDF 會整頁縮小，所以要拆頁。
- 上限：每個品牌 50 份、每份 80 個播放項目、30 個自訂頁面。
- 伺服器不產生 PDF 檔。`decks.export_pdf` 回傳列印版網址，由瀏覽器另存為 PDF。
- `decks.delete` 會讓分享連結失效，要兩段確認。

## 8. 交付前驗收

- [ ] 只讀標題，故事講得通。
- [ ] 每個數字都有來源，或已標明概算、情境、示範。
- [ ] 搜尋沒有 TBD、佔位字或假資料。
- [ ] 最密的頁在投影解析度下不用捲動，字從教室後排也看得清楚。
- [ ] 有背景照片的頁，文字清楚可讀。
- [ ] 所有 QR Code 與連結實際打開過。
- [ ] 換頁、簡報筆與 PDF 都實際試過。
- [ ] 公開設定符合使用者的意思。
- [ ] 回報時講清楚哪些沒驗證，例如需要真實帳號的流程。
